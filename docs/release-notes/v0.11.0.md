# ArenaDesktop 0.11.0

This release reaches you from **v0.8.0** — 0.9.0 and 0.10.0 were never published on their own — so it carries three versions' worth of change. Two of them are new writing surfaces and a new way to reach everything; the third closes the gap that the second left open.

If you are on **v0.8.0 x64**, this is a safe update: no shortcut changed, no menu item disappeared, and every window you had still opens the way it did.

- **0.9.0 — the prompt pad.** A small scratchpad for the prompt you only want once. *Ctrl+Shift+P.*
- **0.10.0 — the command palette.** One list for the whole app, plus the layout cycle's missing key and a pad that keeps what you were typing. *Ctrl+K* and *Ctrl+Shift+K.*
- **0.11.0 — the palette covers the menu.** The last dozen ⋯ menu items, the five named zoom levels, and a test that stops the two drifting apart again.

## The prompt pad (0.9.0)

Battle Lab is the library: it keeps prompts, groups them, queues them, journals what happened. That is exactly right for the prompts you come back to, and exactly wrong for the one you thought of on the bus.

Press **Ctrl+Shift+P** and one small window opens: a box for the prompt, a picker for the Arena page, and a copy button. Write or paste the prompt, pick the page, choose **Copy & open** (it names the page) or press Ctrl+Enter. ArenaDesktop puts the text on the clipboard and brings that page forward with the keyboard already in it. Press Ctrl+V.

ArenaDesktop never types into arena.ai and never reads the page. It copies, it navigates, and the paste is yours — the same rule Battle Lab's copy button has always followed. *Copy & open* is worded that way on purpose: it does not claim the paste happened, because it hasn't.

The pad remembers the last ten prompts in `prompt-pad.json`, reopens on the page you chose last, fills `[blank]` placeholders with Battle Lab's own dialog, and asks before copying anything past 6,000 characters. Since 0.10.0 it also **keeps what you were typing**: closing the pad no longer throws away an unsent prompt, and copying clears the draft because the prompt is in the remembered list by then.

## The command palette (0.10.0)

By 0.9.0 the app had around thirty things it could be asked to do, spread over four menus, a tray icon and nine Ctrl+digits — and one thing it could *not* do: the three window layouts lived in a submenu with no key between them, even though the rule for cycling them had existed in Core since v0.2.0.

Press **Ctrl+K**. A box appears. Type a few letters and press Enter.

```
   Ctrl+K                    sett                   Enter
┌────────────────┐    ┌───────────────────────┐    ┌──────────────┐
│ ▏               │ →  │ Open Settings  Ctrl+, │ →  │ Settings     │
└────────────────┘    └───────────────────────┘    └──────────────┘
```

Search works the way Settings and Help already work: every word you type must start a word in the command's name or keywords, so `zoom reset` goes to 100% and `sett` is enough for Settings. Move with **↑** and **↓** with the caret staying in the box, run with **Enter**, close with **Esc**. The keys printed beside a row are the keys that actually work, including any you remapped.

**Ctrl+Shift+K** cycles the layouts — Standard → Compact Focus → Left Rail → Standard — and the same cycle is in ⋯ → **View** → **Layout** → *Cycle layout* and in the palette, because a Core rule that nothing can call is not a feature.

## The palette covers the menu (0.11.0)

The 0.10.0 palette was not quite finished: the ⋯ menu still held about a dozen commands it had never learned, which made it a second, smaller app rather than a second door onto the same one. Now it has them all — *View the log…*, *Open log folder*, *Export a support bundle…*, *Connection security…*, *About ArenaDesktop*, *Save as PDF…*, *Open in a new window*, *Quick ask* (which focuses the Arena page, ready to type — until now the tray and `--ask` were the only ways there) and *Lock ArenaDesktop* — plus **the five named zoom levels**: 50%, 75%, 100%, 150%, 200%.

The zoom levels are generated from the same list the View menu's Zoom submenu draws on, so the two can never disagree. 100% carries **Ctrl+0**, because that key already did it, and its keywords still include "reset" and "normal".

### Two commands that know when to stay out of the way

The palette asks the window a question before it lists anything: *does this one apply?*

- **Lock ArenaDesktop** appears once a lock exists. Before that it is not a command that would fail — it is simply not there.
- **A named zoom level** appears only when the current range can hold it. With the extended range off, 150% and 200% are absent; turn it on and they arrive.

The count under the list follows what is available, so "12 of 49" never implies that eleven commands went missing.

### And a test that keeps it honest

A palette that covers the menu drifts the first time somebody adds a menu item, unless something notices. So a test now parses the ⋯ menu, collects every click handler, and refuses to pass unless each one is a palette command or an exemption **with a written reason** — the find bar's own buttons, the recovery overlay's buttons, the pinned-mode rows, the parameterised mode rows, and the items that just open a submenu.

Add a menu item tomorrow and CI asks you to make the same decision the rest of the menu already made.

## The small print, honestly

- **The palette runs commands, not arguments.** It cannot take an address, a profile name or a search string. Commands that need a value stay where they were.
- **The palette keeps no history.** No recency ranking, nothing written down about what you ran.
- **Prefixes only.** `sett` finds Settings; `etting` finds nothing. Deliberate: three search boxes in this app should answer the same way.
- **The cycle is a cycle.** Ctrl+Shift+K goes in one fixed direction; pick a layout outright in Settings, the Layout submenu, or the palette.
- **The pad's draft and its remembered prompts are plain text.** `prompt-pad.json` is unencrypted, like Battle Lab's library — a prompt or a half-written draft naming something private sits there until you Forget it or copy the prompt.
- **Pinned mode stays out of the palette.** Pinning depends on where you are; a palette row for it would need a palette that knew the current page, which this app deliberately does not.

Everything else you had is unchanged: the three layouts, Battle Lab in its side pane, the field pass, profiles, downloads, the app lock, the updater, `--prompt-pad`, `--palette` and their `arenadesktop://` links.

**Honest status:** the build, the full test suite, the published binary's start-up and its WebView2 initialisation are verified by CI on a Windows runner. Interactive behaviour — keystrokes in the palette, the two conditional rows, an installer run, an update — is **Unverified** until the on-machine pass in `RELEASE_CHECKLIST.md` runs on a real Windows PC. That pass now includes the prompt pad, the palette and its hidden commands.
