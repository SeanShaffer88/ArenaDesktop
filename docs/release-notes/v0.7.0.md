# ArenaDesktop 0.7.0

Two changes to the app's shape rather than its features: it ships for x64 only, and the ⋯ menu is organised into five groups instead of one long list.

If you are on **v0.6.0 x64**, this is a small, safe update.

## The ⋯ menu is grouped

It had grown to a flat list of thirty entries at the top level, so finding one meant reading all of them. The top level is now five groups:

| Group | What is in it |
|---|---|
| **Navigate** | Arena modes, per-mode pinning, Back / Forward / Home / Reload, restore last closed page |
| **View** | Zoom presets, focus mode, always-on-top, the three layouts, find, this session, connection security |
| **Page** | Print, save as PDF, copy page address, open in browser, open in new window |
| **Tools** | Downloads, Battle Lab, field pass, keyboard shortcuts, lock now |
| **Help** | Help, view log, open log folder, diagnostics, export support bundle, about |

Profile switching, Settings and Check for updates stay at the top, where they were. **Nothing was removed and no shortcut changed.** Every command is one or two clicks away.

The three layouts are now one **Layout** submenu rather than three checkable siblings mixed in with "always on top" and "focus mode" — they are a single choice, so they read as one.

**Back, Forward, Home and Reload are now in the menu.** They were keyboard-only (Alt+← / Alt+→ / Alt+Home, F5) and had no visible entry anywhere. They sit at the foot of **Navigate**, through exactly the same dispatch as the keys.

The key shown beside Settings and Home now follows your remappings. Both are rebindable in Settings, so those two hints are read from the shortcut catalog rather than written into the menu — if you have moved Settings off Ctrl+, the menu says so. Back, Forward and Reload are fixed and always read Alt+←, Alt+→ and F5.

## ARM64 builds are gone

v0.7.0 ships **x64 only**: no ARM64 CI job, no `-arm64.exe` installer, no `-windows-arm64.zip`. A release now carries three assets instead of five.

The honest reason: ARM64 was carried because the fork base's CI built it, not because anyone asked for it, and **it was never actually run through the on-machine pass on real hardware**. Shipping an unverified native build is worse than not offering one.

**If you are running an ARM64 build of 0.6.0 or earlier, you stay on it.** Your install keeps working. The updater still names your architecture, finds no matching installer in a newer release, and offers you nothing — it will not silently hand you x64 binaries. There is no update path to 0.7.0 for ARM64, and that is a deliberate choice rather than a bug.

Two ways forward if you want 0.7.0 on a Windows-on-ARM PC:

1. **Run the x64 build under emulation.** Download the x64 installer; Windows on ARM will run it. This works, and it is what most Windows-on-ARM software does — but it is not the same as a tested native build, and it is not tested as such.
2. **Stay on 0.6.0 arm64.** Nothing breaks, and nothing new arrives.

## Nothing else changed

No feature behaviour changed in this release. If you skip it, you are not missing a fix.
