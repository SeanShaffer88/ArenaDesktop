# ArenaDesktop 0.12.0

A small release about one sentence the app kept saying and not meaning.

The prompt pad exists for the prompt you only want once. That has always come with a footnote: *anything you mean to keep belongs in Battle Lab*. Which was true, and which meant that the moment you decided you **did** want to keep the thing you had just written, the app made you do it by hand — copy the prompt, open the Lab, click New prompt, paste it, name it, pick a category.

Now the pad does it. This release also refreshes the README, which had been quietly describing v0.1.0's download names for eleven versions.

If you are on **v0.11.0**, nothing you already use has moved.

## Save to Battle Lab

There is a new button beside **Copy & open**, and it answers to **Ctrl+S**:

```
┌───────────────────────────────────────────────────────┐
│  Write one prompt…                                    │
│                                                       │
│                    [ Save to Battle Lab ] [ Copy & open ]
└───────────────────────────────────────────────────────┘
        files it, named after the first line
        └─► Battle Lab → prompts → category "Prompt pad"
```

The prompt lands in the library under a **`Prompt pad`** category, named after its first line (trimmed to 60 characters, with "2", "3"… added if that name is taken), and the line under the box says where it went: *Saved to Battle Lab · Write a limerick about deadlines.*

The box keeps its text afterwards. Keeping a prompt and copying one are different intentions, and you may want both — so saving does not clear the box, does not clear the draft, and does not close anything.

### It refuses what the library already has

- **The same text is not added twice.** The comparison is the body, with surrounding whitespace ignored, against the whole library — wherever the original came from. The pad answers *Already in Battle Lab · (its name)* and changes nothing.
- **At the 200-prompt cap** it says the library is full and adds nothing, rather than quietly growing the file past the limit the Lab itself enforces.
- **Names do not collide.** Two prompts that open with the same line become "…" and "… 2" instead of two identical rows in the list.

### One writer, because one file

`battle-lab.json` belongs to the Lab, and the pane keeps it in memory while it is open. So the pad never opens the file itself when the Lab exists: it asks the main window, which routes the prompt through the **live library** the pane is showing (and refreshes its list) — and only opens the store when the Lab has never been built, when there is no second copy to fight with.

The prompt's text is never written to the log. The log records that a handoff happened and how it ended, not what you wrote.

## README, brought up to date

The install section still told you to download `ArenaDesktop-Setup-v0.1.0-x64.exe`. It now names the current version, points at the latest release, and mentions that every release ships `SHA256SUMS.txt` so you can check what you downloaded with `certutil`.

It also learned about the last three versions: the command palette and the prompt pad are in the feature list, `battle-lab.json` and `field-pass.json` are in *Where things live*, portable mode now says which files it carries, and there is a **How complete is it?** section that points at QUALITY.md, KNOWN_LIMITATIONS.md and RELEASE_CHECKLIST.md instead of implying the app is finished.

## The small print, honestly

- **The handoff is one-way.** The pad can file a prompt in the Lab; the Lab cannot send one back to the pad, and a prompt kept from the pad is an ordinary Lab prompt afterwards — edit it, move it to another category, delete it, all in the Lab.
- **No category picker.** Every handoff goes to `Prompt pad`. Renaming the category in the Lab afterwards is fine; the next handoff will create it again.
- **The name is the first line**, not a request for one. If that is not what you would have called it, rename it in the Lab.
- **The pad still keeps its own ten.** A prompt kept in the Lab and copied to Arena both stay where they are; the remembered list and the library are separate on purpose.

Everything else is unchanged: the three layouts and their cycle, the palette and its coverage of the menu, profiles, downloads, the field pass, the app lock, the updater.

**Honest status:** the build, the full test suite, the published binary's start-up and its WebView2 initialisation are verified by CI on a Windows runner. Interactive behaviour — including this handoff, with the Lab open and closed — remains **Unverified** until the on-machine pass in `RELEASE_CHECKLIST.md` runs on a real Windows PC; v0.12.0 adds its checks there.
