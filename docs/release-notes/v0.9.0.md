# ArenaDesktop 0.9.0

A small release about one thing: the prompt you only want once.

Battle Lab is the library. It keeps prompts, groups them, queues them, and journals what happened — which is exactly right for the prompts you keep coming back to, and exactly wrong for the prompt you thought of on the bus. Filing it feels like work, and typing it straight into Arena means losing it the moment the box is cleared.

So this release adds the **prompt pad**.

If you are on **v0.8.0**, nothing you already use has moved: no shortcut changed, no menu item disappeared, and Battle Lab, Quick ask and the Arena modes work exactly as they did.

## The prompt pad

Press **Ctrl+Shift+P** and one small window opens: a box for a prompt, a picker for the Arena page, and a copy button. Or open it from ⋯ → **Tools** → *Prompt pad…*, the tray menu, `--prompt-pad`, or an `arenadesktop://prompt-pad` link — every route lands on the same single pad.

Write or paste the prompt, pick the page, choose the **Copy & open** button — it names the page — or press Ctrl+Enter. ArenaDesktop puts the prompt on the clipboard and brings that page forward with the keyboard already in it. Press Ctrl+V.

That last step is the whole design, and it is not a shortcut:

```
   you type              the pad copies            you paste
┌──────────────┐      ┌───────────────┐      ┌────────────────────┐
│ a prompt     │  →   │  clipboard    │  →   │ Arena's prompt box │
└──────────────┘      └───────────────┘      └────────────────────┘
                        ArenaDesktop stops here ↑
```

ArenaDesktop never types into arena.ai and never reads the page. It copies, it navigates, and the paste is yours — the same rule Battle Lab's copy button has always followed. *Copy & open* is worded that way on purpose: it does not claim the paste happened, because it hasn't.

**Enter** is a new line (prompts are often more than one line), **Ctrl+Enter** copies, **Esc** closes.

### It remembers ten prompts, and the page you picked

The pad keeps the last ten prompts you copied, newest first, in `prompt-pad.json` beside your settings. Double-click one (or select it and press Enter) to load it back into the box. **Forget** removes the selected prompt; **Forget all** empties the list. Neither touches the text in the box, and nothing in the list is sent anywhere — it is your PC and nothing else.

The page picker offers all nine Arena modes and starts on the one you used last, so a pad that always sends you to Battle stops doing that the first time you choose Direct Chat.

### Blanks and long prompts behave like the Lab

A prompt containing `[topic]`-style placeholders shows **Fill blanks…**. It opens the very same dialog Battle Lab uses, and the filled text goes back into the box — so what you see is what will be pasted, not what might be.

A prompt longer than 6,000 characters asks before it is copied, with its exact size, because Arena's prompt box has a limit ArenaDesktop cannot see. It does not truncate or refuse: it asks, and your answer decides.

### The clipboard clear covers it

If you have turned on Settings → Behavior → *Clear copied prompts from the clipboard after…*, a pad copy is cleared on the same schedule as a Battle Lab copy. The pad closes the instant it copies, so the countdown is kept by the main window instead — otherwise the setting would quietly stop applying to anything copied from the pad. It still never clears while the app is locked, and it still only ever clears text ArenaDesktop itself put there.

## The small print, honestly

- **The box is not a document.** Closing the pad with unsent text loses it. Battle Lab is where anything you mean to keep belongs.
- **The list is not a library.** Ten prompts, no categories, no search, no queue, no journal. That is the point.
- **Remembered prompts are plain text on disk**, like Battle Lab's library. A prompt naming something private sits there until you Forget it.
- **No export from the long-prompt warning.** Battle Lab offers to export an over-long prompt as a .txt file; the pad only offers copy-anyway, because a second save dialog in a scratchpad is friction rather than safety.

Everything else you had is unchanged: the three layouts, Battle Lab in its side pane, the field pass, profiles, downloads, the app lock, the updater. Windows runtime behaviour remains **Unverified** until the on-machine pass in `RELEASE_CHECKLIST.md` runs on a real Windows machine — this release makes no new claim about it, and adds the prompt pad's checks to that pass.
