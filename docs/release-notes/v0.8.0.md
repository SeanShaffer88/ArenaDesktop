# ArenaDesktop 0.8.0

This release reaches you from **v0.6.0** — 0.7.0 was never published on its own — so it carries two versions' worth of change. Both are about the app's shape rather than new features: Battle Lab now sits beside the page, the ⋯ menu is grouped instead of being one long list, and the build ships for x64 only.

If you are on **v0.6.0 x64**, this is a safe update and nothing you already use has moved.

## Battle Lab sits beside the page now

Battle Lab used to open in a window of its own. Running a prompt meant looking at the Lab, copying, then switching windows to paste — and if you wanted to log the result afterwards, switching back. The two things you need at the same time were never on screen at the same time.

It is now a pane inside the main window, beside the Arena page, with a splitter you can drag:

```
┌──────────────────────────┬─┬────────────────────┐
│                          │ │  Battle Lab        │
│      Arena page          │ │  prompts · editor  │
│                          │ │  run queue         │
│                          │ │  results journal   │
└──────────────────────────┴─┴────────────────────┘
```

The page is never covered — the pane takes width from it, and the splitter is how you decide how much. Everything else about the Lab is unchanged: the same prompt library, the same blanks, the same run queue, the same manual results journal, the same JSON file. Closing the pane and reopening it puts you back on the prompt you were editing, with the same filters.

Open it the same three ways as before (⋯ menu → **Tools** → Battle Lab, the tray menu, `--battle-lab`, or an `arenadesktop://battle-lab` link), or with the new **Ctrl+Shift+B**, which opens it and closes it.

### It fits the space it is given

The Lab was drawn for a 1220-pixel window: a 272-pixel prompt list, a flexible editor, and a 356-pixel journal. Dropped into half a window unchanged, that would have left the editor about a hundred pixels wide, which is not an editor.

So the pane changes shape with its width:

| Pane width | Layout |
|---|---|
| 940px and wider | Three columns, exactly the old window |
| 600–939px | Prompt list and editor side by side, journal stacked underneath |
| Under 600px | One column at a time, chosen by **Prompts / Editor / Journal** tabs |

In the tabbed layout the pane follows what you do — copying a prompt or adding a new one switches to the editor rather than leaving you on the list you just used.

**There is a floor, and the app is honest about it.** Two panes need at least 706 pixels of width. Below that, ArenaDesktop widens the window first. If it still will not fit — a small screen, or a window already at the edge — the status bar says *Battle Lab needs a wider window*, and you stay on the page rather than getting two unusable slivers. Dragging the splitter can never push the page below its own minimum either; the divider stops where it would.

### What went away

The Battle Lab window. There is no "open Battle Lab in its own window" option, because the point was to stop having one. Everything it did it still does, in the pane.

If you relied on moving the Lab to a second monitor while you worked on the page on the first, that is no longer possible — and it is the one real trade in this change. The alternative would have been keeping both, and two Battle Labs editing one library is a worse problem than a pane you cannot move.

## The ⋯ menu is grouped

The menu had grown to a flat list of thirty entries at the top level, so finding one meant reading all of them. The top level is now five groups:

| Group | What is in it |
|---|---|
| **Navigate** | Arena modes, per-mode pinning, Back / Forward / Home / Reload, restore last closed page |
| **View** | Zoom presets, focus mode, always-on-top, the three layouts, find, this session, connection security |
| **Page** | Print, save as PDF, copy page address, open in browser, open in new window |
| **Tools** | Downloads, Battle Lab, field pass, keyboard shortcuts, lock now |
| **Help** | Help, view log, open log folder, diagnostics, export support bundle, about |

Profile switching, Settings and Check for updates stay at the top, where they were. **Nothing was removed and no shortcut changed.** Every command is one or two clicks away, and the Lab's own item now reads **Hide Battle Lab pane** while the pane is open.

The three layouts are one **Layout** submenu rather than three checkable siblings mixed in with "always on top" and "focus mode" — they are a single choice, so they read as one.

**Back, Forward, Home and Reload are now in the menu.** They were keyboard-only (Alt+← / Alt+→ / Alt+Home, F5) and had no visible entry anywhere. They sit at the foot of **Navigate**, through exactly the same dispatch as the keys.

The key shown beside Settings and Home follows your remappings. Both are rebindable in Settings, so those two hints are read from the shortcut catalog rather than written into the menu — if you have moved Settings off Ctrl+, the menu says so. Back, Forward and Reload are fixed and always read Alt+←, Alt+→ and F5.

## ARM64 builds are gone

This release is **x64 only**: no ARM64 CI job, no `-arm64.exe` installer, no `-windows-arm64.zip`. A release now carries three assets instead of five.

The honest reason: ARM64 was carried because the fork base's CI built it, not because anyone asked for it, and **it was never actually run through the on-machine pass on real hardware**. Shipping an unverified native build is worse than not offering one.

**If you are running an ARM64 build of 0.6.0 or earlier, you stay on it.** Your install keeps working. The updater still names your architecture, finds no matching installer in a newer release, and offers you nothing — it will not silently hand you x64 binaries. There is no update path for ARM64, and that is a deliberate choice rather than a bug.

Two ways forward if you want this release on a Windows-on-ARM PC:

1. **Run the x64 build under emulation.** Download the x64 installer; Windows on ARM will run it. This works, and it is what most Windows-on-ARM software does — but it is not the same as a tested native build, and it is not tested as such.
2. **Stay on 0.6.0 arm64.** Nothing breaks, and nothing new arrives.

## Nothing else changed

No other feature behaviour changed in either of these versions. If you skip this release, you are not missing a fix.
