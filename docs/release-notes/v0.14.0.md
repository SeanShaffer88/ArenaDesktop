# ArenaDesktop 0.14.0

This one came from a screenshot. Somebody reported *"Error message when accessing Settings"*, and the app's answer was a dialog that said "details were written to the log" — no exception, no frame, no next step. v0.13.0 fixed the dialog. This release fixes what the dialog exposed: the app had no idea which of its own files was broken, no memory of its own crashes, and made its owner do by hand four things it could take as an argument.

## It can see its own data

Diagnostics now carries a **Data files** block: every store ArenaDesktop owns — settings, download history, Battle Lab, prompt pad, field pass, privacy stats, and the crash ledger — with its size and a verdict in words.

```
Data files (this PC)
  settings.json — ok (4.2 KB)
  downloads.json — ok (18.9 KB)
  battle-lab.json — unreadable: '{' is an invalid start of a value…
  prompt-pad.json — not created yet
```

Beside it, **Repair data files…** does the one safe thing: it copies each unreadable file next to itself with the app's own `.corrupt-<timestamp>` name, and only then deletes the original so the app can start that file fresh. If the copy fails, the original stays — the worst outcome of pressing the button is nothing happening.

## It can see its own crashes

A crash now leaves a record, in all three places one can happen:

- the **UI thread** (the dialog you already know),
- a **background thread** — previously a silent process death with a log line,
- a **task nobody awaited**.

The ledger is `crash-history.json`. A clean exit clears its marker, so the next launch can say **"The last run ended in an error"** in the status bar — a fact, not a guess — with the detail in Diagnostics. Three crashes inside ten minutes is treated as a loop, and the dialog then offers **Restart in safe mode** instead of only a report.

## The palette takes arguments

Ctrl+K had fifty commands and no arguments: `zoom 125` was a search for a command with that name. Four verbs now work, and the row for what you asked appears first:

| Type | What happens |
| --- | --- |
| `zoom 125` | The page at 125% (a percentage the page can do) |
| `find cables` | The find bar opens with "cables" in it |
| `profile Work` | The app restarts into that profile |
| `mode side` | Side by Side, in one jump |

Anything malformed — `zoom 900`, an unknown profile — stays a search. The palette does not clamp, guess, or open web addresses from the box, and the text you type after `find` is never written to the log.

## Blanks that carry their own answer

A prompt can now say `Write about [topic] in a [tone=neutral] voice`. `tone` is still a blank; `neutral` is what it becomes if you leave that field alone. Your own value still wins, a defaulted blank is no longer reported as "left as it was", and plain `[topic]` behaves exactly as it did.

## And three things for the person who has to prove it works

- **The field pass exports itself** — **Export report…** writes Markdown for a person or JSON (`schemaVersion` included) for a tool. Verdicts and notes only, as ever: nothing from the Arena page.
- **The journal shows which prompts win** — a cross-prompt leaderboard (battles, A wins, B wins, ties) appears in "Copy journal" once more than one prompt is recorded.
- **`scripts/verify-windows.ps1`** runs the start-up smoke test, scans the log for errors, asks for a verdict on each release-checklist item, and writes `docs/verification/verify-<stamp>.md`. That file is what the "Unverified" rows in QUALITY.md are waiting for. `-NonInteractive` records "Not recorded" rather than inventing a result.

The High Contrast support that shipped in v0.9.0 is now audited by a test: every brush the shell paints with must have an override, and the override must still be re-applied when Windows' preference changes.

## About ARM64

A CI job publishes `win-arm64` self-contained and checks WebView2's arm64 loader is in the payload, so the target cannot rot silently. **Nothing ships it** — no asset, no installer, and a guard test keeps it that way. If you are on Windows-on-ARM, you still run the x64 build under emulation.

## What this does not do

- **It still does not fix the original crash.** It makes that crash findable: the data inventory names a broken file, the ledger names the run, and Diagnostics carries both. If your Settings window fails, the banner names the step — that string is the fix.
- **A repaired file starts from defaults.** Nothing is lost (the copy is beside it), but it is not merged.
- **The Battle Lab "next in queue" hotkey did not ship.** It needs a second global hotkey — a setting, a capture UI and a registration lifetime — and that is its own slice rather than an afternoon's bolt-on.

**Honest status:** CI builds it, runs the full suite, publishes both RIDs, and starts the x64 exe once. Everything interactive above — the repair button, the safe-mode relaunch, the palette arguments, the exports — is **Unverified** until somebody runs `scripts/verify-windows.ps1` on a real PC. That script is this release's attempt to make that one run cheap.
