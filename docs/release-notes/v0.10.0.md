# ArenaDesktop 0.10.0

A keyboard release, mostly about not hunting through menus.

By v0.9.0 the app had around thirty things it could be asked to do, spread over four menus, a tray icon, nine Ctrl+digits, and a handful of Ctrl+Shift keys. That is fine to learn once and tiring to use every day. It also had one thing it could *not* do: the three window layouts lived in a submenu with no key between them, even though the rule for cycling exists in Core since v0.2.0. It waited because the app this one takes its shell design from keeps its layout cycle inside a command palette, and ArenaDesktop did not have one.

So this release adds the palette, and the cycle comes with it.

If you are on **v0.9.0**, nothing you already use has moved: no shortcut changed, no menu item disappeared, and every window opens the way it did.

## The command palette — Ctrl+K

Press **Ctrl+K**. A box appears. Type a few letters and press Enter.

```
   Ctrl+K                    sett                   Enter
┌────────────────┐    ┌───────────────────────┐    ┌──────────────┐
│ ▏               │ →  │ Open Settings  Ctrl+, │ →  │ Settings     │
└────────────────┘    └───────────────────────┘    └──────────────┘
```

What it finds:

- **The nine Arena modes** — `battle`, `side`, `leaderboard`, `video`. Each shows the Ctrl+digit that already does the same thing.
- **Every window** — Settings, Downloads, the Battle Lab pane, the prompt pad, the field pass, the shortcut list, Diagnostics, This session…, Help, Check for updates.
- **The window's own shape** — the three layouts, the new cycle, focus mode, always-on-top.
- **The page and the zoom** — Find, Back, Forward, Home, Reload, Restore the last closed page, zoom in / out / reset to 100%, Print, Copy the page address, Open in your browser.

Search works the way Settings and Help already work: every word you type must start a word in the command's name or keywords, so `zoom reset` goes straight to *Reset zoom to 100%*, and `sett` is enough for Settings. Prefixes, not fuzzy matching — the same query always gives the same order, in all three places.

Move with **↑** and **↓** (the box keeps the caret), run with **Enter**, close with **Esc**. The keys printed beside a row are the keys that actually work: if you changed the Settings, Downloads or Home key, the palette shows yours.

With an empty box it lists everything, grouped — which turns out to be a decent way to find out what the app can do.

### It is a second door, not a second app

Every command in the palette is one the menus or the keys already run. The palette decides nothing on its own: it hands back an id and the main window dispatches it to the very same handler the menu item calls. That is why it can never type into arena.ai, read the page, or do something the menus will not — it has no code path of its own to do it with.

It also refuses to open while the app is locked, from every route: the key, the menu, the tray item and an `arenadesktop://palette` link all reach the same place, and that place checks the lock first.

## A key for the layout cycle — Ctrl+Shift+K

Standard → Compact Focus → Left Rail → Standard. One gesture, also in ⋯ → **View** → **Layout** → *Cycle layout*, and in the palette as *Cycle the window layout*.

You can still pick a layout outright — Settings → Appearance & toolbar, or the three checkable items in the same submenu — and this release adds three palette commands for that too, so Ctrl+K can reach every layout by name.

## The prompt pad keeps what you were typing

The pad from v0.9.0 closed with your unsent text still in it, and that text was gone. For a surface that exists to hold a half-written prompt, that was a poor deal. Close the pad now — or lose it to a stray Esc — and the text comes back the next time you open it.

It is stored in `prompt-pad.json` beside the remembered prompts, and portable mode carries it with everything else. Copying a prompt clears the draft: by then the prompt is in the remembered list, and reopening with the same text twice would be a surprise rather than a convenience.

## The small print, honestly

- **The palette takes no arguments.** It cannot accept an address, a profile name or a search string. Commands that need a value (a link, a page) stay where they were.
- **The palette keeps no history.** No recency ranking, no "things you use", nothing written down about what you ran. That would be a settings surface and a privacy question, not a launcher.
- **Prefixes only.** `sett` finds Settings; `etting` finds nothing. Deliberate: four search boxes in this app should answer the same way.
- **The cycle is a cycle.** Ctrl+Shift+K goes in one fixed direction; it cannot jump from Standard straight to Left Rail. Pick that in Settings, the Layout submenu, or the palette.
- **The draft is plain text.** `prompt-pad.json` is unencrypted, like Battle Lab's library — a draft naming something private sits there until you copy it or clear the box.

Everything else is unchanged: the three layouts, Battle Lab in its side pane, the field pass, profiles, downloads, the app lock, the updater. This release's Windows runtime behaviour is **Unverified** until the on-machine pass in `RELEASE_CHECKLIST.md` runs on a real Windows machine; the palette and the pad's draft add their checks to that pass — Ctrl+K with focus in the page and in the shell, the palette while locked, the draft surviving a crash, and the cycle landing on the label the status line claims.
