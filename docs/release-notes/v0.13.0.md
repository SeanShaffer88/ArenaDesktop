# ArenaDesktop 0.13.0

This release starts with a bug report that was a screenshot of an error box:

> **ArenaDesktop hit an unexpected error but kept your session safe.**
> Details were written to the log:
> `C:\Users\SeanShaffer\AppData\Roaming\ArenaDesktop\logs\arenadesktop.log`

That dialog was true and it was useless. It named no exception, no code, and no way to turn "it broke" into a fix — and Settings, the window you open *because* something is wrong, was the window that would not open.

So this release fixes both halves.

## The app now says what broke

The unexpected-error box shows the exception and where in the app it was thrown:

```
ArenaDesktop hit an unexpected error.

What happened
  System.InvalidOperationException: Sequence contains no elements
  Where: ArenaDesktop.SettingsWindow.UpdateProfileButtons()

Log
  C:\Users\…\AppData\Roaming\ArenaDesktop\logs\arenadesktop.log

[ Copy details ]  [ Open log folder ]  [ Close ]
```

**Copy details** puts a bounded report on the clipboard: the version, the OS, the exception, the innermost cause, the app frame that threw — and the last 25 lines of the log, cut at about 4 KB so it stays a paragraph. **Open log folder** opens the folder the log is in, for when you would rather read it yourself.

The log tail is trimmed by exactly the same rule the app's *errors, warnings, info, unparsed* filter already uses before you share anything. There is no "send report" button and no upload: the report leaves your machine only when you paste it somewhere. That was the privacy promise before this release and it did not get a crash-shaped exception.

And the handler itself cannot crash the app: if the report window cannot be built for any reason, it falls back to the plain message box — with the exception summary in it — and nothing is lost.

## Settings opens even when a panel fails

Every load-time step that touches the disk, the registry or the page now runs under its own guard. If one throws, the app logs which step it was (`Settings: the profile list failed: …`) and shows a banner at the top of the window:

> **Some settings could not be shown.**
> the profile list. The rest of this window works, and the log has the details.

The banner sits outside the searchable sections, so typing in the search box cannot hide it. Everything else in Settings loads and works normally. Before this, any single throw in that sequence meant the window never appeared — which is what the screenshot showed.

If the window cannot be constructed *at all*, it now says which window and why ("Settings could not open." plus the exception summary) instead of an anonymous error, and the same goes for a main window that fails to start.

## Offline help for the box itself

There is a new Help page — *"ArenaDesktop showed me an error — what now?"* — that explains what the two buttons do, why the report is safe to paste, what the log is, and what `--safe-mode` is for when it happens at launch. It works with no network, like the rest of the Help pages.

## What this does not do

- **It does not fix the crash behind the screenshot.** It makes that crash findable: the next occurrence names the exception and the throwing frame, and the log names the Settings step. That is the missing information, not the missing fix.
- **It does not catch everything.** The dialog covers exceptions on the UI thread. A crash on a background thread that bypasses it still ends the process; the log is where to look, as before.
- **A guarded panel is degraded, not repaired.** When the banner names one, its controls are still there but empty until the underlying problem is fixed.

**Honest status:** CI builds the app, runs the full Core suite, publishes it and starts it once. Nobody has yet clicked *Copy details* on a real Windows machine, so the dialog, the fallback and the banner are **Unverified** — v0.13.0 adds the on-machine checks, including the deliberately damaged settings that reproduce the report above.
