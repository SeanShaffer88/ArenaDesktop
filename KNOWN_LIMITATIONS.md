# Known limitations

Honest list of what ArenaDesktop does not do or has not proven yet. Kept current as work proceeds.

## Verification status

- **Windows runtime: Unverified.** v0.1.0 is built and fully gated on a Linux VM (build 0 errors / 0 warnings + the full Core test suite). Nothing about real Windows behaviour — sign-in persistence, tray, downloads, voice, updates — is claimed until the RELEASE_CHECKLIST.md pass runs on a real Windows machine. In particular, v0.15.0's Settings restyle has not yet been observed on Windows, in the Light theme, or with Windows High Contrast.
- Arena's live routes (Battle home, `/leaderboard`) were set from the site's public structure on 2026-10-27; a live in-app confirmation is part of the same field pass.

## Product limits

- **Inside Direct Chat and Side by Side, you pick the model(s).** ArenaDesktop takes you to the right page; the model choice at the top of those pages is Arena's own picker — the app never injects script into the page, so it cannot choose for you.
- **Battle Lab lives in the main window.** Since v0.8.0 it is a side pane, not a window, so it cannot be dragged to a second monitor — the page and the Lab share one window by design. In a narrow window the pane folds to one tabbed column, and below 706px of content width the split is refused outright (the status bar says so) rather than showing two unusable columns.
- **Battle Lab results are recorded by hand.** The app never reads anything from the Arena page, so the results journal only contains what you log yourself (A won / B won / Tie plus your note); winners are never detected automatically.
- **The field pass records your own verdicts.** Its nine checks are steps you perform by hand; the pass stores the Pass / Problem / Skip marks and notes you enter and does not verify anything by itself.
- **Arena has no voice dictation.** There is no microphone button in Arena's prompt box (checked on the live site, 2026-10-27). For voice, click in the prompt box and use Windows dictation (Win+H); ArenaDesktop's Quick ask (tray / `--ask`) just gets you to the page, focused and ready to type.
- **Portable mode does not carry your sign-in.** Settings, download history, logs and the prompt pad's remembered prompts travel in the `data` folder beside the exe; the WebView2 sign-in profile stays in `%LOCALAPPDATA%`.
- **The app lock guards the open app only.** It does not encrypt your sign-ins or settings on disk, and the app says so wherever the lock is described.
- **Rollback covers one previous version**, and only a version that was itself reached through the in-app updater.
- **Seamless updates — two honest edges.** (a) **Updating FROM v0.3.0 or older is closed by the installer's fallback, not the handshake.** Those builds don't know `--exit-for-update`: they tolerate the flag and merely wake their window, so the new installer waits, then asks the process to close its main window (a close-to-tray build may hide to the tray instead of exiting), then force-closes it if it still hasn't gone. The update is still fully automatic and the app still relaunches afterwards — the exit is just less gentle that one time. The clean handshake applies once both sides speak it. (b) **Rollback keeps the old flow.** Reinstalling the previous version from Diagnostics launches a kept installer that predates this feature: it shows its classic wizard (you click through it), the app exits so setup can take over, and nothing relaunches ArenaDesktop afterwards — you start it yourself when the rollback finishes.
- **Update checks need a published release to find.** Before the first ArenaDesktop release exists on GitHub, Check for updates reports it couldn't find release information.
- **Unsigned binaries.** There is no code-signing certificate; Windows SmartScreen may warn on first run (More info → Run anyway).
- **Architectures:** x64 only since v0.7.0 — ARM64 is *built* by CI from v0.14.0 so the publish cannot rot, but no ARM64 build is published or supported.
- **A crash report is not a crash *handler* for every thread.** The dialog covers exceptions on the UI thread. Since v0.14.0 a crash on a background thread or an unobserved task is *recorded* (`crash-history.json`, and the log), and the next launch says the last run ended in an error — but the process still ends, and Windows decides how. Nothing is uploaded in any case.
- **The report says where in the app, not what you were doing.** It carries the exception, the throwing frame and the log tail — not your prompt, your page, or a screen recording. If a crash only happens after a specific sequence, that part is still yours to describe.
- **A guarded Settings panel is degraded, not fixed.** When the banner names a panel, that panel's controls are still there but empty; the failure and its step name are in the log so it can be diagnosed, and the rest of the window is unaffected.
- **Profile settings exports do not contain sign-ins or site data.** They move profile preferences only. The profile's WebView2 folder contains cookies and local site data; the new folder button opens it for manual copy/restore, but copying while ArenaDesktop is open can capture an inconsistent database. Exit the app first. Windows-protected cookies usually work only for the same Windows user on the same PC; the app does not provide a one-click, cross-PC sign-in migration.
- **The v0.16.0 accessibility and visual pass is not observed yet.** Automated checks pin control-search navigation, accessible names and live-region declarations, but Narrator, keyboard-only flow, text scaling, Light theme and Windows High Contrast still require the on-machine checklist. No new screenshots have been fabricated.
- **One screenshot so far.** Captures come from real Windows runs only, so the set is owed rather than borrowed: the main window is in the README, and the other six are listed in `docs/screenshots/CAPTURE.md` as they are taken.
- **Downloads history follows this app's activity.** While the window is open, ArenaDesktop refreshes history after a download completes or fails and after local delete or clear actions. Reopen the window to refresh after external edits.
- **The session window's numbers are this-run-only.** Pages, time on Arena, mode jumps, downloads and copied prompts are counted in memory and vanish when the app closes; time only counts while the window is on screen, and gaps over four hours are ignored.
- **Pinned mode is a shortcut, not a setting that changes behavior.** It adds a status-bar jump and two ⋯ items; it never changes which page a launch opens.
- **A repaired data file starts from defaults.** "Repair data files…" copies the unreadable file beside itself first, so nothing is lost, but the app then reads the fresh default rather than merging whatever could be salvaged — recovering the old file by hand is the way back.
- **A defaulted blank is filled by its default.** `[tone=neutral]` means the prompt's author already answered; supply your own value to override it. Nothing about a stored prompt changes until it is copied.
- **Duplicate detection compares prompts, not intent.** It reports identical text (whitespace and case folded) and reused names — it can't know whether two prompts were meant to be different. The pad's handoff uses the strictest version of this: the same body adds nothing, even if you have since edited the saved copy's name or category.
- **Keeping a prompt creates the library if it was never opened.** The first write seeds `battle-lab.json` with the same four sample prompts a first launch of the Lab would — that is the library's own rule, not something the pad adds, and they can be deleted immediately.
- **A handed-off prompt is named after its first line.** The pad derives the name itself (trimmed to 60 characters with an ellipsis) and appends "2", "3"… when that name is taken; rename it in the Lab if the first line is not what you would have called it. The category is always `Prompt pad` — the pad does not offer a category picker.
- **The prompt pad holds one prompt at a time.** It is not a document: since v0.10.0 closing it keeps what was in the box as a draft, but there is one box, one draft and no history beyond them, and the remembered list is not searched, categorised, queued or journaled — it is just the last ten prompts you copied, newest first. Anything you mean to keep goes to Battle Lab with **Save to Battle Lab** (Ctrl+S, v0.12.0), which files it under a `Prompt pad` category.
- **The pad's long-prompt check has no export.** A prompt past 6,000 characters asks before it is copied (with its exact size), but the pad offers only copy-anyway; exporting a long prompt as a .txt file is Battle Lab's affordance.
- **Remembered pad prompts and the unsent draft are plain text on disk.** `prompt-pad.json` is not encrypted, exactly like Battle Lab's library: a prompt or a half-written draft naming something private sits there until you Forget it (or, for the draft, until you copy the prompt or clear the box and close).
- **The long-prompt warning guesses no limit.** ArenaDesktop can't see Arena's prompt-box length limit, so it warns above 6,000 characters and offers an export; it never truncates or refuses the copy.
- **The command palette takes five arguments, not an address.** Since v0.14.0 it understands `zoom <percent>`, `find <text>`, `profile <name>` and `mode <name>`; since v0.14.0 `saved <text>` finds one of your Battle Lab prompts and copies it. Matching is by words in the name first and the prompt's own text last, so a prompt whose body happens to contain the words you typed can be found — a shortlist of matches is shown in Battle Lab rather than one being picked, and there is no fuzzy spelling: a typo finds nothing. It deliberately does not open web addresses from the box (links have their own policy), it keeps no history, and it does not learn from what you type.
- **The palette covers the ⋯ menu, minus the rows that only make sense in place.** Since v0.11.0 every menu item has a command or a written reason it has not — the exceptions are the find bar's own buttons (Next, Previous, Close, the options), the recovery overlay's buttons, the pinned-mode rows (which depend on what you are browsing), the parameterised mode rows (covered by the nine mode commands) and the items that just open a submenu. A test fails if a new menu item is neither.
- **A command that cannot work is hidden.** *Lock ArenaDesktop* appears only when a lock is set, and a named zoom level appears only when the active range can hold it — so the palette can list fewer commands than the catalogue holds, and the count under the list counts what is actually available.
- **The layout cycle is a cycle, not a choice.** Ctrl+Shift+K steps Standard → Compact Focus → Left Rail in that fixed order; it cannot jump straight from Standard to Left Rail. Settings → Appearance and the ⋯ menu's Layout items and the palette's three *Use the … layout* commands are how you pick one outright.
- **Downloads history never stores source URLs** — a downloaded file can be opened, shown in its folder, or deleted, but not re-downloaded from history after the session's retry window.
